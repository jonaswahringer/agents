The user is handing you an **aside**: information relevant to the work, delivered out of band. It is context, not a new task. The current task stays the current task.

## Steps

1. **Absorb the aside.** Restate it in one sentence so the user can see you took it in correctly. If it contradicts something already established (a plan, an assumption, earlier instructions), name the conflict and say which version now wins.
2. **Fold it in.** Decide where the aside lands and act on that tier:
   - _Changes work already done this session_ — apply the correction now, then return to the task.
   - _Changes work still ahead_ — adjust the plan and carry on; say what changed.
   - _Durable beyond this session_ (who the user is, standing preference, project constraint) — save it to memory, and say you did.
   - _Pure context_ — hold it; no action needed.
3. **Resume.** Pick the interrupted task back up exactly where it was. Done when the task is moving again and the reply spent no more than a few sentences on the aside.

If there is no task in flight, the aside is simply absorbed (and saved if durable) — acknowledge in a sentence and stop.
